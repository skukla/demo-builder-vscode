# Step 04 — Say what the extension writes

Replace "This storefront's owner controls its code; Demo Builder does not change it." with a
sentence that is true: Demo Builder adds the pieces that connect the storefront to the demo
(the product-page fallback, block libraries, the content and store settings, the description
file) and leaves the storefront's own code alone unless the SC accepts a fix. The card line
for the boilerplate: "Built on Adobe's Commerce boilerplate 4.0.1; Demo Builder's current one
is 6.0.0. N of Demo Builder's fixes fit this code." Copy reviewed with the owner before it
ships; pinned by the caveat tests.

## The Storefront report (decision 7)

One rendering of the diagnostics storefront section (step 07), in SC words, with headings:
Where this storefront comes from (boilerplate, version, gap, lineage); What Demo Builder wrote
(the integration pieces, with dates); Demo Builder's fixes (applied / fit / missing, by
consequence, with the offer button where fits remain); Product pages (the pre-render state);
Content (source site, index). Doors: the projects-list card menu ("Storefront report"), the
Welcome card menu for an added demo (the same report for the source repository, without the
"wrote" section), the completion card's "See the storefront report", the dashboard's
storefront card, and the agent tool. The projects-list card itself shows nothing new beyond
the one origin line.
