# PL-48 — read the most repetitive suites, fix what reading finds

The evidence behind every rule in the goal text. Read once; it does not change between
candidates.

## What this item is NOT

It is not a consolidation programme. **Consolidation does not move the redundancy metric** —
measured in Phase 1, where `fieldValidation`'s three suites became tables, 647 lines became
322, every assertion got stronger, and the number did not shift by one point. 90 tests became
99, still 100% redundant, minimal covering set still 6. `it.each` emits one test per row and
the rows still overlap in what they catch.

`fieldValidation` has since gone from 84/90 to **90/90**. Consolidation makes the ratio
WORSE.

## A high ratio means "many tests, few decisions" — which has two causes

The number cannot tell them apart, and only reading can:

- **Real repetition.** `fieldValidation`: one test written ninety times with different data.
  `sanitization`: nine tests asserting one rule against nine characters.
- **Arithmetic.** `adobeEntityService` ranked 50/51 and is a 76-LINE FACTORY with two
  decisions, whose tests belong to `AdobeEntityFetcher` (fourteen suites, already 100%).
  `pdpUrlEncoding` ranked 24/26 and is a model suite — already table-driven, documented with
  its ADR and its cross-repo byte-identical contract.

**Recording a candidate as arithmetic is a complete, successful outcome.** Say so and move on.

## What reading actually finds — the payoff

None of this is visible in any metric:

- **A production defect.** `withTimeout` never checked `signal.aborted`, so an already-aborted
  AbortSignal was ignored and the caller waited out the whole timeout. It reaches a
  THIRTY-MINUTE timeout on project creation: a build the user cancelled reported a timeout.
- **Assertions that cannot fail.** Now banned by `tests/sop/no-disjunction-assertions.test.ts`,
  so that specific shape is gone tree-wide. The weaker cousins are NOT banned and need
  judgement: 629 bare `toBeDefined`, 618 `not.toContain`, 42 `toBeTruthy`. Each is weaker than
  an exact assertion and each is often right.
- **Weak assertions that hide string mutants.** `sanitization` had five reading
  `not.toContain('](')` — true of ANY mangling, not just the correct one. The regexes make the
  exact output knowable, so each row became `toBe`. That alone took the module 97.06% → 100%
  with behavioural survivors unchanged at zero.
- **An uncovered decision.** `fieldValidation`'s composition order, which nothing tested.
- **Dispatcher tests that would pass with a broken switch**, because a VALID value cannot
  distinguish routing from fall-through — both arms return the same object.

## The method, per candidate

1. **Read the module first.** How many decisions does it actually have? A thin factory or a
   constants file explains the ratio by itself.
2. **Read the test names.** Repetition looks like one rule against many inputs.
3. **If it is arithmetic:** record that on PL-48 with the reason and stop. Do not consolidate.
4. **If it is real repetition:** convert to `it.each` tables whose ROWS ARE THE INPUTS.
5. **Keep the labels.** In `sanitization` each test name carried the security rationale —
   which Markdown construct the character would have opened. Those became row labels
   verbatim. The label is usually the only thing the one-test-per-case form carried that a
   table does not.
6. **Assert exact values.** Derive them from the source rather than guessing; every exact
   expectation derived this way has passed first time.
7. **Re-measure and hold the ratchet.** The module's open-gap count must not rise.

## Traps

- **Do NOT target the minimal covering set.** It is what the SCORE needs, not what a reader
  needs. A case worth naming is worth keeping even when another test catches the same
  decision.
- **Anchor rewrites on a LINE START** (`^import `). Matching `import ` anywhere hit prose
  inside a doc comment twice in one day and truncated files mid-sentence.
- **A rename or a new suite forms a test FAMILY**, and `tests/sop/test-family-setup.test.ts`
  requires a shared `.testUtils`. It reads GIT-TRACKED files, so `git add` before trusting it.
- **Both typecheckers, not just jest.** `@swc/jest` strips types, so a type error passes the
  suite and fails `tsc`.
- **A fix that adds a branch needs BOTH arms tested.** The `signal.aborted` fix left an
  `if (true)` mutant alive: six tests covered the line and none killed it, because the nearest
  candidate raced an already-resolved promise that wins either way.
